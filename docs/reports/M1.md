## 5. Findings during M1

**Security finding: Podman's `mounts.conf` reached every container (#15, fixed in #124).** An
entry `<host dir>:/run/secrets/<name>` in the user's `~/.config/containers/mounts.conf` was copied
by Podman into the container's run directory and bound at `/run/secrets/<name>` in every
Sallyport container: workspace, harness and inference. A system `mounts.conf`
(`/etc/containers`, `/usr/share/containers`) would have been read the same way when no user file
existed. Sallyport never writes such a file; the exposure needed one placed by the user or by
another tool running as the user.
- **Which commits had it.** Every commit from the first launch path, `de3fbaf` (Task 6b, merged
  as PR #16, 2026-11-10), up to the merge of #124. #11 (the same task) is where Podman was
  claimed hermetic, and its test passed for the wrong reason.
- **Why the test missed it.** That test ran `ls /run/secrets` and asserted the canary's name was
  absent. `ls` prints only the copied directory's name, never the file inside it, so the test
  passed while the canary was mounted. The fixed test looks inside (`[ -e ]`, `ls -R`), and a
  control proves the same probe finds the canary when the defences are off. Every red-team row
  that asserts an absence now has such a control (#140, #144 to #146, #148, #150, #164).
- **Mechanism.** Podman builds the OCI spec, and with it the `mounts.conf` subscriptions, at
  `podman init`, a separate process from `create`. Only `create` got `--default-mounts-file`,
  and the `default_mounts_file` key of `containers.conf` is ignored on Podman 4.9.3.
- **Found by** the OCI config verifier (RT-SUP-04), the first time it compared a real config
  with the argv's intent.
- **Fixed by** three independent defences, each with a test that fails when it is removed:
  Podman's `HOME` is a private empty directory; `init` and `start` carry the empty mounts file;
  the verifier refuses any mount the argv did not ask for. THREAT_MODEL.md §6 records the residual.
- **Open.** Hosts where Podman adds mounts of its own (a system `mounts.conf` if the flag ever
  stops working, FIPS mode) get every launch refused as `config-mismatch` (#121, M6). No
  advisory: the README states pre-alpha.

Other security fixes found by review during M1, each merged with its test: credential masking
before the cut in proxy request text (#165) and in sandbox-chosen audit text (#177); manifest
diagnostics never echo a credential (#200); Podman found only in root-owned system directories
(#131); a Podman stdout over its cap is refused (#180); live sessions bounded at 64 (#205).

Merged since this list was first written, each from the security review (§9):
- #260 and #279: a CLI launch (`sally session start`, `sally sandbox run`) refuses a manifest
  kept inside one of its own `rw` or `brokered` mounts, shows the summary, each warning and each
  acknowledged risk, and needs consent bound to the manifest text read (a typed `yes` on a
  terminal, or the text's hash); `sallyd` audits each acknowledged risk and warning before the
  launch (RT-MAN-03, RT-MAN-02). `sessions.create` itself shows and asks nothing.
- #284: a symlinked mount root written with a trailing `/` or `/.` is refused; the default data
  and state homes and the folder of a binary that `config.toml` names are denylist rules; on WSL
  a mount root on a Windows drive is refused by its filesystem kind (RT-FS-05, RT-FS-06,
  RT-FS-11). #320 makes that last check read the kind as the mount table's type name, 9p or
  virtiofs; a drive on a WSL the checks do not detect, or over a type not listed, is not
  refused yet (#281, open).
- #326: the launch summary escapes manifest text, quotes globs and MCP arguments, and names the
  settings that differ from their defaults; a glob with a leading or trailing space is refused

## 8. Open risks

THREAT_MODEL.md §6 lists the residual risks accepted for v1, each with its planned upgrade; open
weaknesses are marked OPEN there with their issues, listed in §6 above. The ones that matter most
for using M1 as it stands:
- Podman drops resource limits silently on cgroup v1; `sally doctor` fails on v1.
- `sessions.attach` (`sally sandbox run`) runs a command in any live session's workspace with no
  approval, for any process of the user's uid that can open `control.sock`.
- A `sallyd` killed outright stops none of its containers and audits nothing about them. Conmon's
  timeout ends each workspace and harness container `runtime.timeout` + 300 s after its `init`
  (RT-AG-16), and the next start's orphan sweep removes anything left; an inference container has
  no bound until that next start.
- `--security-opt label=disable` on every role: SELinux hosts lose label confinement (#29).
- An interpreter registered in `binfmt_misc` with the `F` flag runs inside sandboxes (#21).
- Audit redaction matches a secret's forms only; a sandbox that transforms a value it holds
  writes it past the redactor.
- RT-AG-09 (#141): an unexplained local failure on a must-pass row; the exit does not wait for
  it. A fork bomb can also reach `runtime.memory`: the kernel may then kill inside the
  container, its init included, which ends the session (possible, not observed; none planned).
- Kept staged data has no deletion path in M1 (SI-11): every stopped session's stage stays, up
  to `runtime.stage_size` each; no product command deletes it, and removing it by hand needs
  `podman unshare`. It is inert, and `sally session changes` lists it (#216, M4.5).
- `sally audit verify` exits 0 for a log whose files and head are gone and for a log that runs
  past its head (#268, its verify part). Acceptance line 2 stays met as written: a tampered byte
  fails the check.
- Keep a manifest outside every folder any manifest mounts `rw` or `brokered`: the launch gate's
  place check sees only the text being launched and that manifest's own mounts (#254, #255).
  A hash that ships with a manifest launches it unread; never use a hash that came with the
  manifest (none planned).
- A spliced tunnel (any allowed host without a secret grant) is checked only by its CONNECT
  host. The bytes inside are not read, so a TLS server name or an inner `Host` header can name
  another site served at the same address, such as another tenant of a shared CDN. Prefer exact
  host rules off shared CDNs. Until the tunnel check in §7 lands, the tunnel also carries any
  protocol, plain HTTP included, on an allowed port.
- Until Exit item 5 merges: a launch whose cleanup fails twice can leave a container that no
  session supervises. Conmon's timeout still ends it (RT-AG-16), and the next start's orphan
  sweep removes it.
